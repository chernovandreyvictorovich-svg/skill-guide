# Как помочь проекту

Спасибо, что заглянул! Skill-Guide растёт за счёт **русских описаний скиллов** —
автосканер находит скиллы сам, но понятный человеческий текст пишут люди. Это и есть
самый ценный вклад.

## Быстрый старт

```bash
git clone https://github.com/Ntmib/skill-guide.git
cd skill-guide
python3 scripts/validate.py   # проверить, что данные валидны
```

## Добавить или поправить описание скилла

Всё живёт в одном файле — [`data/overrides.json`](data/overrides.json). **Код трогать не нужно.**

1. Форкни репозиторий, создай ветку.
2. Открой `data/overrides.json`. В объекте `"skills"` найди нужный скилл (или добавь новый
   по его имени):

   ```json
   "имя-скилла": {
     "cat": "dev",
     "core": 0,
     "cmd": 1,
     "desc": "Что делает — простым языком, одно-два предложения.",
     "when": "«триггерные фразы», в какой ситуации звать",
     "how": "необязательно — по умолчанию подставится сам"
   }
   ```

3. Проверь локально:

   ```bash
   python3 scripts/validate.py
   ```

4. Открой Pull Request.

### Поля

| Поле | Что это | Обязательно |
|---|---|---|
| `cat` | id категории из блока `"categories"` того же файла (или заведи новую) | да |
| `desc` | описание простым языком | да |
| `when` | когда звать — триггерные фразы под задачи | желательно |
| `how` | как применять; по умолчанию генерится (для `/`-команд «Набери /имя», иначе «опиши задачу») | нет |
| `core` | часто используемый скилл (`1`/`0`) | нет |
| `cmd` | это `/`-команда (`1`/`0`) | нет |

Платформу (Claude/Codex/оба) и GitHub-ссылку генератор определяет сам — их указывать не нужно.

## Стиль описаний

- Простой человеческий русский, без канцелярита и «воды».
- `desc` — что делает и зачем, коротко. `when` — реальные фразы, которыми это зовут.
- Ориентир — уже готовые записи в `data/overrides.json`.

## Другие вклады

- Исправления GitHub-ссылок — `data/links.json`.
- Новые категории — блок `"categories"` в `data/overrides.json`.
- Улучшения самого гида (`index.html`) или скриптов (`scripts/`).

## Что проверяет CI

На каждый Pull Request автоматически прогоняется:

- **синтаксис** Python-скриптов;
- **линт** — реальные ошибки (неопределённые имена и т.п.);
- **валидация данных** (`scripts/validate.py`) — структура, ссылки на категории;
- **страж приватности** — что в PR не попали генерируемые/личные файлы
  (`data/skills-data.js`, `usage.json`, `updates.json`).

Красный CI = смотрим, что не так, и правим. Зелёный — можно мержить.

## Важно про приватность

Не коммить машинно-зависимые файлы: `data/skills-data.js`, `data/usage.json`,
`data/updates.json` — они генерируются локально и уже в `.gitignore`. Страж в CI это ловит.

Будь доброжелателен — это маленький дружелюбный проект. Спасибо за вклад! 🙌
